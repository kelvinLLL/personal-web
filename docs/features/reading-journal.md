# Reading Journal

## Goal

Build a private reading journal for books, starting with Japanese literature, where the owner can record reading status, personal reflections, ratings, and high-quality quoted sentences for each book.

Success for the first backend slice means the API can persist private journal entries, quoted passages, and invitation-only comments without making the journal publicly browseable.

## Scope

In scope:

- owner-only CRUD for reading journal entries
- book metadata for title, author, original title, translator, publisher, language, and tags
- reading state, rating, short impression, and longer reflection
- quoted passages with source location, chapter, tags, and owner note
- per-entry share token generation for invitation-only comment access
- visitor comment creation through a share token
- owner moderation for pending, approved, and rejected comments
- JSON-file persistence under the backend data directory
- backend tests for store behavior and API auth/privacy boundaries
- private owner frontend route for listing, creating, editing, sharing, and moderating entries
- shared visitor frontend route for reading the narrow shared view and submitting a comment

Out of scope:

- public reading-journal pages
- user accounts for commenters
- full social/community review features
- web-search or recommendation-agent integration
- rich text editor implementation
- migration to a relational database
- importing copyrighted full text or quotes from web sources without owner-provided text

## Current Design

The existing backend uses FastAPI routers, Pydantic models, and small JSON stores for feature-local persistence. The first reading-journal backend slice follows that pattern instead of introducing a database.

The domain terms are:

- `ReadingJournalEntry`
  - one private owner record for one book
  - owns the book metadata, reading status, rating, reflection fields, quotes, share token, and comments
- `BookNote`
  - the embedded book metadata on an entry
  - intentionally separate from the legacy reader catalog, because this slice is about reflection rather than file reading
- `Quote`
  - a saved sentence or passage from the book, with optional page, chapter, location, tags, owner note, and spoiler flag
- `JournalComment`
  - visitor response attached to one entry
  - created through a share token and stored as `pending` by default
- `Share token`
  - unguessable per-entry capability string
  - the only public access path for visitor comments in this slice

Owner endpoints require the existing admin bearer token:

- `GET /api/reading-journal`
- `POST /api/reading-journal`
- `GET /api/reading-journal/{entry_id}`
- `PUT /api/reading-journal/{entry_id}`
- `DELETE /api/reading-journal/{entry_id}`
- `POST /api/reading-journal/{entry_id}/share-token`
- `GET /api/reading-journal/{entry_id}/comments`
- `PUT /api/reading-journal/{entry_id}/comments/{comment_id}`
- `DELETE /api/reading-journal/{entry_id}/comments/{comment_id}`

Visitor endpoints do not expose the private owner journal list. They require a valid share token:

- `GET /api/reading-journal/shared/{share_token}`
- `POST /api/reading-journal/shared/{share_token}/comments`

The shared view should return only a narrow book summary, owner-selected public-facing impression text when present, and approved comments. It must not expose private long reflections, private quotes, rejected comments, or the full owner library.

The first frontend slice should make that backend usable without pretending the journal is public:

- `/reading-journal` loads owner entries through the admin token from the existing Settings login state.
- When admin auth is missing, the page shows the journal concept and a Settings CTA instead of silently hiding the surface.
- The owner page uses a hand-journal visual language: warm paper background, red seal accent, compact status/rating stamps, ruled quote cards, and calm form panels.
- The owner page should avoid dashboard/admin framing. Its primary layout is a bound notebook: cover/header, left book-index tabs, a ruled-paper reading page, stationery-like action buttons, and note-card sections.
- Owner-facing visible labels can be Chinese/Japanese toned where it improves warmth, while API contracts and route names stay unchanged.
- The owner form is intentionally plain text and textarea based; this keeps data portable and avoids committing to a rich editor before the writing workflow is proven.
- Share-token creation is an explicit owner action per entry.
- Comment moderation happens inline on the selected entry, with pending comments visually distinct from approved or rejected comments.
- `/reading-journal/shared/:shareToken` renders only the backend shared view and allows a visitor to submit a display name plus comment body.

The backend slice is now implemented:

- `backend/models/reading_journal.py` defines the journal entry, book metadata, quote, visitor comment, shared view, and moderation payload contracts.
- `backend/services/reading_journal_store.py` persists entries to `reading-journal.json`, creates share tokens, adds pending visitor comments, filters approved shared comments, and hides private fields from shared responses.
- `backend/routers/reading_journal.py` exposes owner-authenticated CRUD/moderation routes and unauthenticated token-scoped visitor routes.
- `backend/main.py` injects `reading_journal_store` into app state and includes the router.
- `backend/tests/test_reading_journal_store.py` verifies store-level privacy and moderation behavior.
- `backend/tests/test_reading_journal_api.py` verifies auth requirements, owner CRUD, token-scoped commenting, and private-field hiding.
- `.gitignore` excludes generated reading-journal data files because the journal can contain private user-authored reflections and quotes.

The first frontend slice is now implemented:

- `frontend/src/features/reading-journal/page/ReadingJournalPage.tsx` provides the private owner workspace with auth gating, entry list/detail selection, create/edit/delete actions, share-token generation, quote display, and inline comment moderation.
- The owner page visual treatment now uses a notebook cover, warm ruled paper, left-side book index tabs, a Japanese-style serif font stack for the journal area, stamp-like metadata, and stationery-colored actions.
- `frontend/src/features/reading-journal/components/EntryForm.tsx` keeps the writing workflow notebook-like and portable with plain inputs and textarea fields for reflections and quotes.
- The owner form uses Chinese notebook labels, warm paper fields, subtle ruled textarea backgrounds, and stationery-like submit/cancel controls.
- `frontend/src/features/reading-journal/components/CommentList.tsx` presents visitor comments as gentle margin notes requiring owner review, not a moderation table.
- `frontend/src/features/reading-journal/page/SharedReadingJournalPage.tsx` renders the token-scoped visitor view and keeps private reflection/quotes out of the shared response.
- The route and navigation layer exposes `/reading-journal` and `/reading-journal/shared/:shareToken`, and the home feature grid links to the owner surface.
- Frontend tests cover the API adapter, owner page workflows, shared visitor comments, home link, and router resolution.

Recent owner-library syncs are local data operations, not public content publication. When adding books from web research, use the source search only for metadata and legal acquisition links, leave reflections/quotes empty or clearly marked as owner-to-fill, and let the gitignored backend JSON store remain private.
